# CAS Platform — doğrulanmış sürüm tabanı (version constraints)
#
# NE İŞE YARAR
# requirements*.txt "neye ihtiyacımız var" der: doğrudan import edilen ya da
# systemd'nin çağırdığı paketler, neden orada oldukları yazılı. Bu dosya ise
# "hangi sürümlerle doğruladık" der: o listenin TRANSİTİF KAPANIŞI dahil,
# production'da kurulu olan sürümler.
#
# Neden gerekti: temiz bir venv'e `pip install -r requirements-dev.txt`
# yapıldığında 22 transitif paket production'dakinden farklı sürümde geldi
# (starlette 1.2.0 -> 1.6.0, numba 0.64 -> 0.67, typing_extensions 4.10 -> 4.16,
# urllib3 2.0.7 -> 2.7.0 ...). Yani CI'ın yeşil dediği ağaç, servislerin
# çalıştırdığı ağaç değildi. requirements.txt'e transitif paket eklemek bu
# dosyanın çözdüğü sorunu çözmez, sadece "gerçekten import ediyoruz"
# listesini kirletirdi — ayrı dosya olmasının sebebi bu.
#
# NASIL KULLANILIR
#   pip install -r requirements.txt      -c constraints.txt   # runtime
#   pip install -r requirements-dev.txt  -c constraints.txt   # test / CI
#   pip install -r requirements-ml.txt   -c constraints.txt   # ML eğitimi
#   pip install -r requirements-ops.txt  -c constraints.txt   # migration
# `-c` bir kurulum listesi DEĞİL: burada yazan ama requirements'tan
# çekilmeyen paket kurulmaz, sadece kurulacaksa sürümü sabitlenir. Bu yüzden
# dört iş akışının kapanışı tek dosyada durabiliyor.
#
# NASIL GÜNCELLENİR
# Bir bağımlılık bilerek yükseltildiğinde: önce production'da yükselt, sonra
# buradaki satırı production'daki sürüme çek. Sıra bu — bu dosya production'ı
# tarif eder, ona emretmez. Yeni bir doğrudan bağımlılık eklenirse
# requirements*.txt'e ekle, sonra onun getirdiği transitif paketleri de
# buraya ekle (temiz venv'e kurup `pip list` ile bakmak yeterli).
#
# NEDEN TAM LOCK (pip-compile / --require-hashes) DEĞİL
# Tek geliştirici. Hash'li lock her bağımlılık değişiminde yeniden derleme ve
# yeniden hash'leme sürtünmesi getirir; buradaki fayda (aynı sürümlerle
# çalışmak) sürtünmesiz de elde ediliyor. constraints.txt aynı sabitlemeyi
# verir, elle okunabilir kalır ve requirements*.txt'teki gerekçe yorumlarını
# bozmaz. Tedarik zinciri doğrulaması (hash) ayrı bir ihtiyaç; gerektiğinde
# ayrıca ele alınır.
#
# 20 Ağustos 2026'da temiz venv + pytest ile doğrulandı.
